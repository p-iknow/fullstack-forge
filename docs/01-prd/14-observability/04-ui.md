# Observability Domain UI Requirements

이 문서는 admin 관측 대시보드와 알림 설정 화면의 UI 요구사항을 정의한다.

## 화면 범위

- 대상: admin 운영자
- 목적: 장애 징후를 조기 감지하고 복구 판단을 빠르게 수행한다.
- 기본 구성: 관측 대시보드, 알림 규칙 설정, 감사/추적 조회

## 1) 관측 대시보드

- 핵심 KPI 카드 (상단 배치, `01-overview.md` KPI 매핑 참조)
  - 주문 성공률 (목표 98%)
  - 중복 처리 오류 (목표 0건)
  - DLQ 복구 성공률 (목표 95%)
  - 운영 복구 시간 (목표 10분 이내)
  - 리뷰 작성 전환율 (목표 25%)
- 운영 상태 카드
  - queue depth
  - 처리율(worker processed)
  - 실패율(worker failed)
  - DLQ 메시지 수
- 시계열 그래프
  - event processing latency
  - API p95 지연 (KPI: 500ms 이하) 및 p99 지연 (알림: 2초 초과)
  - API 오류율
  - inquiry first response latency (KPI: 24시간 이내)
- 상태 요약
  - 임계치 초과 항목 강조
  - 최근 5분/1시간/24시간 전환

## 2) 큐 운영 패널

- 큐별 backlog 현황과 소비 처리율을 동시에 표시한다.
- 큐별 실패율과 DLQ 이동 추세를 함께 표시한다.
- Queue depth 1000 초과 또는 DLQ 급증 시 경고 상태를 명확히 표시한다.

## 3) 알림 설정 화면

- 알림 규칙 목록: 지표, 임계치, 관찰 윈도우, 활성 상태
- 기본 임계치 초기값 (`01-overview.md §6 알림 임계치` 참조)
  - API 오류율 1% 초과(5분)
  - API p95 지연 500ms 초과(5분)
  - API p99 지연 2초 초과(5분)
  - DLQ 메시지 5건 초과
  - Queue depth 1,000 초과
  - 문의 1차 응답 지연 20시간 초과
- 알림 채널 정책: 운영 채널(예: Slack, Email, Pager) 선택 및 on/off
- 규칙 생성/수정/삭제 시 확인 다이얼로그 표시 (의도치 않은 변경 방지)

## 4) 감사/추적 조회 화면

- traceId 기준 검색으로 주문 단위 end-to-end 흐름을 조회한다.
- eventId 기준 검색으로 특정 실패 이벤트 처리 경로를 조회한다.
- redrive 수행 로그는 실행자/시각/결과를 확인 가능해야 한다.
- 복합 검색 필터: 시간 범위, consumer, 처리 결과(성공/실패), 실패 코드로 필터링 가능
- 검색 결과 목록은 시각 기준 최신순 정렬이 기본이며, 실패 우선 정렬도 제공한다.

## 5) 상호작용 원칙

- 임계치 초과 항목은 색상/배지/상태 태그로 즉시 구분한다.
- 목록과 차트 간 drill-down 동선을 제공한다.
- 운영자가 장애 drill 결과를 기록/조회할 수 있는 진입점을 제공한다.

## 6) 대시보드 갱신 전략

- **자동 갱신 주기**: 30초 간격으로 데이터 자동 갱신 (Prometheus 스크레이프 15초의 2배)
- **수동 새로고침**: 화면 상단에 새로고침 버튼 제공
- **갱신 방식**: API polling 기반 (MVP). WebSocket 실시간 업데이트는 확장 후보
- **마지막 갱신 시각**: 대시보드 상단에 "마지막 갱신: HH:MM:SS" 표시

## 7) 예외 상태 처리

### 빈 상태 (No Data)

- 메트릭 수집 이력이 없는 경우: "아직 수집된 데이터가 없습니다" 메시지와 함께 설정 가이드 링크 표시
- 선택한 시간 범위에 데이터가 없는 경우: "선택한 기간에 데이터가 없습니다" 메시지 표시

### 에러 상태

- Prometheus/API 연결 실패 시: 차트 영역에 "데이터를 불러올 수 없습니다" 오류 메시지 표시. 마지막 성공 데이터가 있으면 stale 표시(회색 배경)와 함께 캐시 데이터 유지
- 부분 실패 시: 실패한 패널만 오류 표시, 나머지 패널은 정상 렌더링

### 로딩 상태

- 초기 로딩: 카드 및 차트 영역에 스켈레톤 UI 표시
- 갱신 중: 기존 데이터를 유지하면서 상단에 갱신 진행 인디케이터 표시 (깜빡임 방지)
