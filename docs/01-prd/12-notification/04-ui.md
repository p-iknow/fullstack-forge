# Notification Domain UI Requirements

## 문서 상태

- 본 문서는 **기존 PRD(01~05)에 미포함된 알림 도메인을 신규 정의**하기 위해 작성되었다.
- MVP UI 범위는 store 앱의 사용자 알림 화면이며 admin 알림 화면은 포함하지 않는다.

## 화면 범위

- 대상: store 사용자
- 위치: 사용자 계정 영역 또는 글로벌 네비게이션의 알림 진입점
- 목적: 최근 알림 확인, 읽음 상태 전환, 미확인 알림 파악

## 핵심 UI 요구사항

- 알림 목록
  - 최신순 정렬
  - 각 항목에 제목, 본문 요약, 생성 시각 표시
  - 항목 클릭 시 관련 화면(order/delivery/review)으로 이동 가능
- 읽음/미읽음 표현
  - 미읽음은 시각적으로 구분되는 배지 또는 강조 스타일 제공
  - 읽음 처리 즉시 목록 상태 반영
- 필터
  - 전체/읽음/미읽음 전환 제공

## 상호작용 정책

- 단건 읽음 처리: 항목 클릭 또는 읽음 액션
- 다건 읽음 처리: 선택 또는 일괄 읽음 액션(선택 구현)
- 빈 상태: 알림이 없을 때 안내 문구와 복귀 동선 제공
- 오류 상태: 일시적 실패 시 재시도 가능 상태 제공

## 비범위

- admin 알림 센터 UI
- 운영 이벤트(장애, 지연, 큐 적체) 노출 UI
  - 해당 영역은 `../14-observability/01-overview.md`에서 별도 관리
- push/email/SMS 설정 화면의 상세 워크플로

## 이벤트 도메인 연결

- 화면에 보이는 데이터는 notifications 큐 소비 결과로 생성된 알림 레코드이다.
- 이벤트 envelope 및 소비 규약은 `../13-event/01-overview.md`를 참조한다.
- fanout 및 신뢰성 운영 기준은 `../13-event/01-overview.md`를 따른다.
