# Notification Domain API Guide

## 문서 상태

- 본 문서는 **기존 PRD(01~05)에 미포함된 알림 도메인을 신규 정의**하기 위해 작성되었다.
- 이 문서는 API 목적/행동 규약만 정의하며 request/response body 스키마는 포함하지 않는다.

## 범위

- store 사용자 알림 목록 조회
- store 사용자 알림 읽음 표시
- admin 알림 API는 제공하지 않음(운영 경보는 observability에서 처리)

## API 1) 알림 목록 조회

- 목적: 로그인 사용자의 알림 타임라인 제공
- 기본 정렬: 최신 생성 시각 우선
- 기본 필터: 전체, 읽음, 미읽음
- 페이지네이션: 커서 또는 페이지 기반 중 하나를 구현 표준에서 선택
- 일관성: 동일 사용자 범위에서 최근 상태가 반영되어야 함

## API 2) 알림 읽음 표시

- 목적: 단건 또는 다건 알림의 읽음 상태 전환
- 보안: 본인 소유 알림만 변경 가능
- 멱등성: 이미 읽음인 항목에 재요청해도 결과는 안정적으로 동일
- 시간 기록: 최초 읽음 시각을 보존하는 정책 권장

## 오류 처리 원칙

- 인증 없음: 로그인 필요 오류 반환
- 권한 없음: 타 사용자 알림 접근 거부
- 존재하지 않음: 삭제되었거나 접근 불가한 알림 식별자 처리
- 부분 실패: 다건 읽음 처리 시 실패 항목 식별 가능해야 함

## 이벤트 도메인 연계

- 알림 생성은 동기 API 호출이 아니라 이벤트 소비 결과로 발생한다.
- 이벤트 envelope 규격은 `../13-event/01-overview.md`를 따른다.
- fanout/멱등/DLQ 운영 원칙은 `../13-event/01-overview.md`를 따른다.

## 비범위

- 이메일, SMS, push 발송 API
- 템플릿 관리 API
- 외부 알림 게이트웨이 연동 API
