# Payment UI

## 대상 화면

### Store (고객)

- 결제 진입 화면
- 결제 진행 화면
- 결제 완료 화면
- 결제 실패 안내 화면

### Admin (운영자)

- 결제 목록 화면
- 결제 상세 화면

## Store 결제 진입 화면

- 주문 요약(아이템, 수량, 금액)과 최종 결제 금액(할인/포인트 적용 후)을 확인하고 결제를 시작한다.
- 결제 수단을 선택한다 (MVP: 카드 단일 수단).
- 결제 시작 시 중복 클릭 방지 상태를 표시한다 (버튼 비활성화 + 로딩 인디케이터).
- 결제 요청에는 idempotency key 기반 중복 방지 정책이 적용됨을 전제로 한다.

## Store 결제 진행 화면

- 결제 처리 상태를 `initiated → authorized → captured` 기준으로 표시한다.
- 상태 갱신 방식: **2초 간격 polling** (`GET /payments/:id`)
- 지연 시 사용자에게 처리 중임을 명확히 안내한다 (진행 바 또는 스피너 + "결제 처리 중입니다" 메시지).
- 최대 대기 시간: **30초**. 30초 타임아웃 도달 시 실패 상태로 전환하고 재시도 동선을 제공한다.

## Store 결제 완료 화면

- 결제 완료 확인 메시지와 결제 요약 정보(금액, 수단, 시각)를 표시한다.
- 주문 상세 페이지로의 이동 링크를 제공한다.

## Store 결제 실패 안내 화면

- 실패 시 결제 실패 코드별 안내 문구를 노출한다:

| failure_code                | 안내 문구                                                           |
| --------------------------- | ------------------------------------------------------------------- |
| `failed_timeout`            | 결제 처리 시간이 초과되었습니다. 네트워크 확인 후 다시 시도해주세요. |
| `failed_gateway`            | 결제 처리 중 오류가 발생했습니다. 잠시 후 다시 시도해주세요.        |
| `failed_insufficient_funds` | 잔액이 부족합니다. 다른 결제 수단을 이용해주세요.                   |

- 재시도 버튼을 제공한다 (최대 시도 횟수 5회 이내일 때).
- 5회 초과 시 "고객센터에 문의해주세요" 안내로 전환한다.
- 중복 결제 우려를 줄이기 위해 마지막 결제 시도 결과 조회 링크를 제공한다.

## Store 환불 안내

- 주문 취소 시 결제 취소/환불이 연결되는 정책을 사용자에게 안내한다.
- 환불 예상 소요 기간: "카드 결제 취소는 3~5 영업일 내 반영됩니다"
- 환불 진행 상태(`refund_requested → refunded`)는 주문 상세와 결제 상세에서 일관되게 확인 가능해야 한다.
- 결제 취소 시 확인 다이얼로그를 표시한다: "결제를 취소하시겠습니까? 취소 후 환불까지 3~5 영업일이 소요됩니다."

## Admin 결제 목록 화면

- 전체 결제 건을 최신순으로 표시한다.
- 필터: 결제 상태, 사용자, 주문 번호, 날짜 범위
- 결제 상태별 건수 요약 (상단 통계)
- 문제 건(`failed`, `refund_requested`) 하이라이트 표시

## Admin 결제 상세 화면

- 결제 정보: 금액, 수단, 상태, PG 거래 ID, 생성/갱신 시각
- 상태 전이 이력 타임라인
- 연결된 주문 정보 링크
- 수동 환불 버튼 (`captured` 상태에서만 활성)
  - 환불 사유 입력 필수
  - 전액/부분 환불 금액 지정
  - 확인 다이얼로그: "환불을 진행하시겠습니까? 이 작업은 되돌릴 수 없습니다."

## 공통 UX

- 모바일/데스크톱 반응형: 결제 화면은 모바일 우선(mobile-first) 설계
- 접근성: 결제 버튼에 aria-label 적용, 에러 메시지 스크린리더 대응
