## 포인트 UI 가이드

본 문서는 store/admin에서 적립 포인트를 노출하고 조작하는 화면 요구사항을 정의한다.

### Store: 포인트 잔액 표시 — `GET /loyalty/balance`

- 마이페이지와 주문 결제 화면에서 포인트 잔액을 노출한다.
- 잔액은 `available`, `pending`, `expired` 상태를 구분해 표시한다.
- 만료 예정 포인트와 유효기간(`expires_at`)을 확인할 수 있어야 한다.
- 적립률(1%)과 최소 사용 포인트(1,000원) 안내를 포인트 영역에 표시한다.
- 조회 결과는 최신 ledger 반영 기준으로 갱신되어야 한다.

### Store: 포인트 사용 UI

- 주문 결제 화면에 포인트 사용 입력/적용 영역을 제공한다.
- `min_redeem_points` 미만 입력은 즉시 차단 또는 안내한다.
- 보유 포인트 초과 입력은 허용하지 않는다.
- 포인트 사용 금액이 주문 총액을 초과하지 않도록 제한한다.
- 동일 주문에서 중복 사용 요청이 발생하지 않도록 상태를 잠근다.

### Store: 사용 결과/실패 안내

- 적용 성공 시 차감 예정 포인트와 최종 결제 금액을 함께 노출한다.
- 거절 시 최소 사용 미달/보유 포인트 초과/중복 사용 등 사유를 구분해 안내한다.
- 주문 취소/결제 취소 시 포인트 복원 결과를 사용자에게 확인 가능하게 제공한다.

### Admin: 포인트 조정 화면

- 사용자별 포인트 잔액, 최근 ledger, 사용 이력을 조회한다.
- 운영자 수동 가감 기능을 제공하며 권한은 `operator|admin`으로 제한한다.
- 조정 시 사유와 요청 ID 입력을 필수로 한다.
- 조정 내역은 감사 추적 가능한 형태로 보관/조회한다.

### Admin: 운영 점검 화면

- 결제/취소/환불과 포인트 ledger 정합성 점검 결과를 확인한다.
- 만료 배치 실행 결과와 잔액 대사 결과를 확인한다.
- 이상 징후(이중 차감 의심, 대사 불일치)는 운영 알림과 연계 가능해야 한다.
