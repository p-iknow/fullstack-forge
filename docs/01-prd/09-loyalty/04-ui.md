## 포인트 UI 가이드

본 문서는 store/admin에서 적립 포인트를 노출하고 조작하는 화면 요구사항을 정의한다.

### 반응형 정책

- **store**: 모바일 우선(mobile-first). 모바일 뷰포트(< 768px)를 기본으로 설계하고 데스크톱은 확장 레이아웃 적용.
- **admin**: 데스크톱 우선(desktop-first). 최소 뷰포트 1024px 기준. 모바일 대응은 MVP 제외.

### 화면 인벤토리

| 화면                   | 앱    | 대상 역할        | 주요 기능                  |
| ---------------------- | ----- | ---------------- | -------------------------- |
| 마이페이지 포인트 잔액 | store | customer         | 잔액 표시, 만료 예정 안내  |
| 주문 결제 포인트 사용  | store | customer         | 포인트 입력·적용·결과 확인 |
| 포인트 내역            | store | customer         | 적립/사용/만료/조정 이력   |
| 사용자 포인트 관리     | admin | operator · admin | 잔액·내역 조회, 수동 조정  |
| 포인트 운영 점검       | admin | operator · admin | 대사 결과, 이상 징후 확인  |

---

### Store: 포인트 잔액 표시

- **노출 위치**: 마이페이지, 주문 결제 화면
- **데이터 소스**: `GET /loyalty/balance`

#### 정보 계층

1. 사용 가능 포인트 (`available_balance`) — 가장 눈에 띄게 표시
2. 적립 대기 포인트 (`pending_balance`) — 보조 정보로 표시
3. 만료 예정 포인트 (`expiring_soon.amount`, `expiring_soon.expires_at`)
4. 적립률(1%) 및 최소 사용 포인트(1,000원) 안내 텍스트

#### 빈 상태 (Empty State)

- 포인트 잔액 0원: "아직 적립된 포인트가 없습니다. 주문 시 결제 금액의 1%가 적립됩니다."
- 신규 가입 직후: 위 메시지와 동일, 포인트 적립 안내 강조

#### 로딩 상태

- 잔액 조회 중: 숫자 영역에 skeleton UI 표시
- 조회 실패: "포인트 정보를 불러올 수 없습니다. 잠시 후 다시 시도해 주세요." + 재시도 버튼

#### 실시간 갱신

- 마이페이지 진입 시 자동 조회 (manual refresh)
- 결제 화면 진입 시 자동 조회
- 실시간 polling/websocket 미적용 (MVP)

### Store: 포인트 사용 UI

- **노출 위치**: 주문 결제 화면 내 포인트 사용 영역
- **데이터 소스**: `POST /loyalty/redeem`

#### 인터랙션

- 포인트 사용 금액 입력 필드 (숫자만 허용)
- "전액 사용" 버튼으로 보유 available 포인트 전체 입력 지원
- `min_redeem_points`(1,000원) 미만 입력 시 즉시 인라인 안내: "최소 1,000원부터 사용 가능합니다."
- 보유 포인트 초과 입력 시 자동으로 보유 잔액으로 제한
- 포인트 사용 금액이 주문 총액을 초과하지 않도록 자동 제한
- 적용 버튼 클릭 후 중복 요청 방지를 위해 버튼 비활성화(lock)

#### 성공 시

- 차감 예정 포인트와 최종 결제 금액을 함께 노출
- 포인트 적용 취소(해제) 버튼 제공

#### 실패 시

- 거절 사유를 인라인 에러로 구분 표시:
  - `below_min_redeem`: "최소 1,000원부터 사용 가능합니다."
  - `insufficient_points`: "보유 포인트가 부족합니다."
  - `exceeds_order_total`: "주문 총액을 초과할 수 없습니다."
  - `duplicate_redemption`: "이미 포인트가 적용된 주문입니다."

### Store: 포인트 내역 화면

- **노출 위치**: 마이페이지 > 포인트 내역
- **데이터 소스**: `GET /loyalty/history`

#### 정보 계층

1. 현재 사용 가능 포인트 (상단 요약)
2. 내역 리스트 (최신순 정렬)
   - 유형 아이콘/라벨 (`적립`, `사용`, `만료`, `조정`)
   - 포인트 금액 (적립: +, 사용/만료: -)
   - 관련 주문 번호 (있는 경우 주문 상세 링크)
   - 일시
   - 만료 예정일 (적립 건에 한해 표시)

#### 필터/정렬

- 유형 필터: 전체 / 적립 / 사용 / 만료 / 조정
- 기간 필터: 1개월 / 3개월 / 6개월 / 직접 입력
- 정렬: 최신순 (고정)
- 페이지네이션: 무한 스크롤 (커서 기반)

#### 빈 상태

- 필터 결과 없음: "해당 조건의 포인트 내역이 없습니다."
- 전체 내역 없음: "아직 포인트 내역이 없습니다."

#### 로딩 상태

- 초기 로딩: 리스트 skeleton UI (3~5행)
- 추가 로딩(무한 스크롤): 하단 spinner

---

### Store: 포인트 복원 안내

- 주문 취소/결제 취소 시 포인트 복원 결과를 알림(notification)으로 확인 가능
- 주문 취소 상세 화면에서 복원된 포인트 금액 표시

---

### Admin: 포인트 조정 화면

- **데이터 소스**: `GET /admin/loyalty/:userId/balance`, `GET /admin/loyalty/:userId/history`, `POST /admin/loyalty/:userId/adjust`

#### 정보 계층

1. 사용자 정보 (이름, ID)
2. 포인트 잔액 요약 (`available`, `pending`, `expired`)
3. 최근 ledger 내역 (테이블, 페이지네이션)
4. 수동 조정 입력 영역

#### 수동 조정 UI

- 조정량 입력 (양수=가산, 음수=차감)
- 사유 입력 (필수, textarea, 최소 5자)
- 요청 ID 자동 생성 또는 수동 입력
- **확인 다이얼로그**: "사용자 {이름}에게 {금액}원을 {가산/차감}합니다. 사유: {사유}. 실행하시겠습니까?"
- 차감 시 available 잔액 부족이면 에러: "사용 가능 포인트가 부족합니다."

#### 접근 제어

- `operator` · `admin` 역할만 접근 가능
- 조정 실행은 감사 로그에 기록

#### 검색/필터

- 사용자 검색: 이름, 이메일, 사용자 ID
- 내역 필터: 유형, 기간 (Store 내역 화면과 동일)

---

### Admin: 운영 점검 화면

#### 정보 계층

1. 대사 결과 요약 (마지막 실행 시각, 불일치 건수)
2. 불일치 상세 목록 (사용자 ID, 기대값, 실제값, 차이)
3. 만료 배치 실행 결과 (마지막 실행 시각, 처리 건수, 실패 건수)

#### 이상 징후 알림

- 이중 차감 의심 건: 동일 주문에 대한 복수 redeem 기록
- 대사 불일치 건: `LoyaltyAccount` 잔액과 `PointLedger` 합계 차이
- 운영 알림 연계: observability 도메인의 알림 채널로 전달 가능

#### 접근 제어

- `operator` · `admin` 역할만 접근 가능
