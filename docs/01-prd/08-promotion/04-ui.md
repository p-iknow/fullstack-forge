# Promotion UI

## 범위

프로모션 도메인의 Store/Admin UI 요구사항을 정의한다.

## 화면 인벤토리

| 화면               | 앱    | 역할          | 설명                              |
| ------------------ | ----- | ------------- | --------------------------------- |
| 쿠폰 입력/적용     | Store | customer      | 주문 과정에서 쿠폰 코드 입력/검증 |
| 할인 비교 표시      | Store | customer      | 후보 할인 비교 및 자동 선택 결과  |
| 프로모션 목록 관리  | Admin | operator/admin| 프로모션 CRUD, 상태 관리          |
| 쿠폰 관리          | Admin | operator/admin| 쿠폰 생성/수정/사용이력 조회      |
| 쿠폰 사용 이력     | Admin | operator/admin| 특정 쿠폰의 사용 이력 상세        |
| 감사 로그 조회      | Admin | operator/admin| 쿠폰 적용/실패/비활성화 이력      |

---

## Store: 쿠폰 입력/적용 UI

### 정보 계층

1. 현재 주문 금액 및 최소주문금액 충족 여부
2. 쿠폰 코드 입력 필드 + 적용 버튼
3. 적용 결과 (할인 금액, 최종 결제 금액)

### 동작 규칙

- 주문 시점에 활성 프로모션 후보 조회(기간/상태 필터) 결과를 사용자에게 표시
- 쿠폰 코드 입력 시 코드 유효성 검증(존재/만료/사용량/사용자별 제한) 결과를 즉시 피드백
- 최소주문금액 조건 검증 결과를 적용 가능/불가 상태로 안내
- 만료 쿠폰은 조회는 가능하나 적용 불가 상태로 표시 (회색 처리 + "만료됨" 라벨)

### 빈 상태

- 활성 프로모션 0건: "현재 사용 가능한 할인이 없습니다" 메시지 표시, 쿠폰 입력 필드는 유지
- 최소주문금액 미달: 쿠폰 입력 필드 비활성화 + "15,000원 이상 주문 시 할인 적용 가능" 안내

### 에러 상태

| 에러 코드                    | 표시 방식      | 메시지 예시                              |
| ---------------------------- | -------------- | ---------------------------------------- |
| `coupon_not_found`           | 인라인 에러    | "유효하지 않은 쿠폰 코드입니다"          |
| `coupon_expired`             | 인라인 에러    | "만료된 쿠폰입니다"                      |
| `coupon_limit_exceeded`      | 인라인 에러    | "사용 한도를 초과한 쿠폰입니다"          |
| `coupon_user_limit_exceeded` | 인라인 에러    | "이미 사용한 쿠폰입니다"                 |
| `promotion_min_order_not_met`| 인라인 경고    | "15,000원 이상 주문 시 적용 가능합니다"  |
| `coupon_already_applied`     | 인라인 안내    | "이미 쿠폰이 적용되어 있습니다"          |
| API 장애                     | 토스트         | "할인 적용에 실패했습니다. 잠시 후 다시 시도해주세요" |

### 로딩 상태

- 쿠폰 검증 중: 적용 버튼 비활성화 + 스피너, 입력 필드 읽기 전용
- 활성 프로모션 조회 중: 할인 비교 영역 스켈레톤 표시

## Store: 할인 비교 표시

### 정보 계층

1. 적용 가능한 할인 후보 목록 (쿠폰 / 카테고리 할인)
2. 자동 선택된 최대 할인 하이라이트
3. 선택 근거 안내 텍스트

### 동작 규칙

- 카테고리 할인 후보 계산(주문 아이템 카테고리 기반) 결과와 쿠폰 할인 후보를 함께 비교 표시
- 쿠폰과 카테고리 할인은 동시 적용 불가(초기) — "할인은 1개만 적용됩니다" 안내
- 사용자에게 더 유리한 할인 자동 선택 — 선택된 항목 시각적 강조 (체크 아이콘 + 배경색)
- 동일 할인액이면 쿠폰 우선(사용자 체감 일관성)
- 선택 근거(`best_price_policy`, `coupon_priority_on_tie`)를 사용자 화면과 주문 이력에 일관되게 반영
  - `best_price_policy`: "가장 큰 할인이 자동 적용되었습니다"
  - `coupon_priority_on_tie`: "동일 할인 중 입력한 쿠폰이 우선 적용되었습니다"

### 빈 상태

- 후보 할인 0건: 할인 비교 영역 비표시 (공간 차지 없음)

## Admin: 프로모션 관리

### 정보 계층

1. 프로모션 목록 (필터: 상태, 타입)
2. 프로모션 상세/편집 폼
3. 상태 전이 액션 버튼

### 동작 규칙

- 할인 정책 본체(타입/할인값/유효기간/활성상태) 관리
- 코드 기반 프로모션 세부(코드/사용 한도/유효기간) 관리
- 카테고리 할인 대상 범위 관리
- 운영자 수동 비활성화, 정책 변경 이력 관리
- 쿠폰 적용 성공/실패 감사 로그 조회

### 상태 전이 UI

| 현재 상태  | 가용 액션                  | 버튼 스타일    |
| ---------- | -------------------------- | -------------- |
| `draft`    | 활성화, 수정, 삭제         | Primary / 기본 / Danger |
| `active`   | 비활성화                   | Warning        |
| `inactive` | 재활성화                   | Primary        |
| `expired`  | (액션 없음)                | —              |
| `deleted`  | (액션 없음)                | —              |

### 확인 다이얼로그

- **비활성화**: "프로모션을 비활성화하시겠습니까? 이미 적용된 주문의 할인은 유지됩니다." + 비활성화 사유 입력 (필수)
- **삭제**: "프로모션을 삭제하시겠습니까? 이 작업은 되돌릴 수 없습니다."
- **활성화**: 확인 다이얼로그 없이 즉시 반영

### 검색/필터

- 프로모션 목록 필터: 상태(`active`, `inactive`, `expired`, `draft`, `deleted`), 타입(`fixed_amount`, `percentage`)
- 쿠폰 목록 검색: 코드 부분 검색
- 정렬: 생성일 내림차순 (기본), 유효기간 종료일 오름차순

### 빈 상태

- 프로모션 0건: "등록된 프로모션이 없습니다. 새 프로모션을 생성해보세요." + 생성 버튼
- 필터 결과 0건: "조건에 맞는 프로모션이 없습니다." + 필터 초기화 버튼

### 에러 상태

- API 장애: 인라인 에러 배너 + 재시도 버튼
- 상태 전이 실패 (`409 Conflict`): 토스트 "상태 변경에 실패했습니다. 최신 상태를 확인해주세요." + 목록 자동 새로고침
- 검증 실패 (`422`): 폼 필드별 인라인 에러

### 로딩 상태

- 목록 조회: 테이블 스켈레톤
- 상태 전이 중: 액션 버튼 비활성화 + 스피너
- 폼 저장 중: 저장 버튼 비활성화 + 스피너

## 반응형 동작

| 화면      | Desktop (≥1024px)        | Mobile (<1024px)          |
| --------- | ------------------------ | ------------------------- |
| Store 쿠폰| 주문 사이드패널 내 배치  | 주문 하단 섹션으로 이동   |
| Store 비교| 후보 가로 나열           | 후보 세로 스택            |
| Admin 목록| 테이블 뷰               | 카드 뷰                   |
| Admin 상세| 2컬럼 레이아웃           | 1컬럼 스택                |

## 실시간 갱신

- Store: 수동 새로고침 (주문 페이지 진입 시 최신 조회)
- Admin 목록: 수동 새로고침 (새로고침 버튼 제공)
- Admin 감사 로그: 수동 새로고침
