# Event Domain UI

이 문서는 admin의 DLQ 관리/redrive 실행 화면 요구를 정의한다.

## 1) 화면 목표

- 운영자가 DLQ 상태를 확인하고 안전하게 redrive를 실행한다.
- redrive 전 원인 분석 필수 절차를 화면에서 강제한다.
- 동일 오류 코드 반복 시 자동 redrive 금지 정책을 반영한다.

## 2) 핵심 화면

- DLQ Queue 목록: queue별 메시지 수, 최근 실패 시각, 장애 유형 요약.
- DLQ 메시지 상세: `eventId`, `eventType`, `traceId`, 오류 코드, payload 요약.
- Redrive 실행 패널: 단건 redrive, 배치 redrive, 실행 사유 기록.
- 감사 로그 화면: redrive 수행 기록, 실행자, 실행 시각, 결과.

## 3) 권한 및 안전장치

- redrive 실행자는 `admin` 권한 필요.
- 실행 전 확인 항목: 원인 분석 완료 여부, 수정 배포 여부, 재실행 범위.
- 실행 후 확인 항목: consumer 독립 처리 확인, DLQ 이동 및 redrive 성공 여부.
- 재시도 한도(`maxReceiveCount` 3)와 보존 기간(source 4일, DLQ 14일)을 화면에 명시해 운영 실수를 줄인다.

## 4) 운영 시나리오 매핑

- 유형 A: Poison Message -> 단건 redrive 후 재검증.
- 유형 B: Queue Backlog 급증 -> queue 우선순위와 처리율 모니터링.
- 유형 C: 외부 의존 장애 -> 복구 후 재처리 정책 적용.

## 5) 비목표

- 이벤트 payload 편집 기능을 제공하지 않는다.
- 자동 무제한 redrive를 제공하지 않는다.

## 6) 표시 규칙

- DLQ 메시지 상세는 payload 원문 대신 필드 요약만 기본 노출하고, 민감정보는 마스킹한다.
- queue/consumer 상태 배지는 `정상`, `지연`, `오류`, `DLQ` 4단계로 통일한다.
